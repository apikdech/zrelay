# zrelay v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build zrelay v2: a zero-disk Go recorder that turns ONVIF-triggered RTSP clips into `zrec` ciphertext in MinIO, serves live view (WHEP) and an RTSP restream, and a zview-server + Svelte SPA that indexes, decrypts and plays those clips in the browser.

**Architecture:** Two Docker containers on the Mac mini. `zrelay` holds one RTSP session and one ONVIF subscription per camera and fans access units out through an in-process Hub to live view, restream and the recorder. The recorder runs ring → clip FSM → fMP4 → zrec writer → in-memory backlog → circuit breaker → S3 multipart. `zview-server` reads MinIO read-only, serves the SPA and the data API, and proxies WHEP signaling. All decryption happens in a browser Web Worker.

**Tech Stack:** Go 1.27 (stdlib `crypto/hkdf`, `iter`, `log/slog`), gortsplib v5, mediacommon v2 `fmp4`, pion/webrtc v4, aws-sdk-go-v2, oklog/ulid v2, prometheus client_golang, go.yaml.in/yaml/v3, testcontainers-go (MinIO); Svelte 5 + Vite + Tailwind + valibot, Vitest, Playwright; Docker/OrbStack.

**Spec:** `docs/superpowers/specs/2026-11-06-zrelay-v2-design.md` (amends `docs/specs/contract.md`, `relay-spec.md`, `ui-spec.md`; the design wins on conflict). Executors read the design doc and the section of the normative spec each task cites.

## Global Constraints

- Module path: `github.com/apikdech/zrelay-v2`. `go 1.27`. Node 26, pnpm 12.
- Strict TDD: no production code without a failing test first (AGENTS.md rule carried over).
- Contract formats are normative and MUST NOT be redefined: `zrec` format_version 1 / suite 1, `zrec.sidecar/2`, `zrec.status/1`, `zrec.coverage/1`, storage layout Contract §7.
- Zero-disk: zrelay MUST NOT create, write or truncate files outside the `local` driver (tests only). No `os.CreateTemp`, no on-disk queues. Production container: `read_only: true`, no volumes, no tmpfs.
- Secrets: only `ENV:` and `FILE:` refs; literals rejected unless `allow_literal_secrets: true`; `KEYCHAIN:` rejected. Logs never contain keys, credentials, DEKs, frame bytes, or URL userinfo.
- Every `--key` CLI flag takes a ref, never a literal.
- All timestamps and storage paths UTC (D9). Video only in clips (D10); live/restream may carry G.711.
- Storage drivers: `s3` and `local` only. Strict config parsing rejects `smb`, `sftp`, `retention`, `mlock`.
- Relay S3 credentials never delete non-dot keys (D15).
- `http_listen` defaults to `127.0.0.1:9464`; never bind metrics publicly.
- Bearer credential = unpadded base64url of the raw 32-byte `K_api`; verifier compares `SHA-256(raw)` in constant time against up to two stored hex hashes.
- Docker-only tooling: `ffmpeg`/`ffprobe` run from a container image (`linuxserver/ffmpeg:version-7.1-cli` or equivalent pinned), never installed on the host.
- Commit after every task, conventional-commit messages, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **RTP timestamp wrap** (32-bit at 90 kHz wraps every ~13.25 h): a camera running for days must keep monotonic DTS and never split or corrupt a clip at the wrap. Test in Task 6 (`TestAccessUnitsMonotonicAcrossRTPWrap`).
2. **Clip spanning UTC midnight / a `max_duration` series crossing days:** the video and sidecar keys come from the *segment's own* start time; zview finds the next segment in the next day's index. Tests in Task 15 (`TestKeysUseSegmentStartDay`) and Task 32 (`TestSeriesNextAcrossMidnight`).
3. **Ambiguous `CompleteMultipartUpload`** (MinIO succeeds but the response is lost; the retry gets `NoSuchUpload`): the driver must treat it as committed when the object exists with the expected size, not drop the clip. Test in Task 18 (`TestCommitRetryAfterLostResponse`).
4. **SIGTERM while the breaker is open with backlog:** the process must exit within `shutdown_grace_seconds`, abort uploads it cannot finish, and log and count each dropped clip as `shutdown` (coverage cannot be published while storage is down). Test in Task 26 (`TestShutdownWithOpenBreakerExitsWithinGrace`).
5. **ONVIF unreachable while RTSP works:** the camera goes `degraded`, live view and restream keep working, no clips are made, coverage records not-ready. Test in Task 9 (`TestEventsDownKeepsVideoAndMarksDegraded`).
